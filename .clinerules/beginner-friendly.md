## Brief overview
- Project rule for working with a beginner programmer and beginner game developer.
- Prioritize clean, maintainable code and solid game-dev practices.
- Explain more advanced ideas in simpler terms when they come up.

## Communication style
- Assume Isak is still learning both coding and game development.
- When discussing more complicated systems, explain them in clear, simple language.
- Prefer practical explanations over jargon-heavy ones.

## Development approach
- Favor best practices that help keep the project organized and maintainable.
- Avoid quick fixes that introduce spaghetti code or make the codebase harder to understand later.
- Prefer solutions that are easier to extend, debug, and learn from.

## Code quality
- Keep code structure clean and readable.
- Prefer small, focused changes over messy or overly clever implementations.
- When making architectural choices, lean toward clarity and maintainability.

## Teaching guidance
- When a solution is not obvious, briefly explain why it is a good practice.
- Call out tradeoffs in simple terms when relevant.
- Help the user learn by making the reasoning understandable, not just by producing the final code.
